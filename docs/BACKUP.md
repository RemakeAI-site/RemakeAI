# Резервное копирование и восстановление

Полная копия студии включает рубрики, публикации, идеи, настройки, файловые метаданные и сами оригиналы. Сохраняйте несколько копий с датами. Перед массовой очисткой, миграцией или обновлением сначала проверьте свежую копию в отдельном окружении.

## Копия через интерфейс

Откройте **Настройки → Данные** или **Система** и выберите экспорт резервной копии. Для небольшого набора браузер скачивает ZIP. Сервер ограничивает браузерный экспорт 64 MiB, 38 объектами с учётом превью и 1000 строками на таблицу. Если превышен хотя бы один предел, используйте CLI.

## Весь проект через CLI

Команды выполняются из папки с `package.json`. Первым параметром передайте адрес работающей студии, вторым — путь к папке копии. Проверьте свободное место, остановите редактирование и загрузки на время экспорта.

```bash
npm run backup -- export http://localhost:8787 ./backups/studio-2026-11-14
```

Храните каталог копии целиком, включая метаданные и двоичные файлы. В обоих вариантах поле `format` в `manifest.json` задаёт версию формата, а `objects/` содержит оригиналы и превью. CLI запрашивает метаданные страницами, записывает медиа потоком в файлы, проверяет размер и SHA-256 оригиналов и публикует манифест по завершении. При восстановлении оригиналы передаются частями до 8 MiB и заново проверяются на сервере. Медиа коллекции могут превышать объём оперативной памяти процесса, а манифест загружается в память.

## Восстановление

1. Подготовьте чистые D1 и R2. Для локальной проверки запустите второй экземпляр с отдельным каталогом данных командой ниже. По умолчанию приложение разрешает процедуру импорта локально. Для облачного экземпляра используйте отдельное окружение и временно установите `BACKUP_IMPORT_ENABLED=1` на время восстановления. Верните значение `0` перед открытием адреса для обычной работы.
2. Для каталога копии используйте CLI. Для небольшого ZIP откройте **Настройки → Данные → Экспорт и восстановление** и выберите файл копии. CLI умеет восстановить браузерный ZIP после его распаковки в каталог.
3. Сравните количество объектов, откройте вложенные рубрики, описание и идеи. Скачайте несколько оригиналов и сравните SHA-256 с исходной копией. Проверьте архив и корзину.
4. После проверки можно переключить адрес рабочего приложения на восстановленные ресурсы. Сохраните исходную библиотеку до подтверждения результата.

```bash
npm run dev -- --port 8791 --inspector-port 9231 --persist-to .wrangler/restore-check
```

В другом терминале:

```bash
npm run backup -- restore http://localhost:8791 ./backups/studio-2026-11-14
```

Значение `BACKUP_IMPORT_ENABLED` определяет возможность записи через импорт на уровне сервера. Если на облачном адресе включить эту возможность, она будет доступна всем, кто может обратиться к адресу. Не включайте импорт на рабочем общедоступном экземпляре с реальными данными во время обычной эксплуатации.

## Внешняя копия на отдельном сервисе

Настройте отдельное хранилище под копии. Используйте собственного поставщика или выделенный аккаунт, где отключён публичный доступ, и отдельный ключ с доступом только к резервному контейнеру. Установите [rclone](https://rclone.org/install/) на обслуживающий компьютер. Команда `rclone config` позволяет создать S3-подключение с параметрами поставщика. Для защиты содержимого можно настроить дополнительное подключение типа [crypt](https://rclone.org/crypt/). Храните пароль шифрования и конфигурацию rclone отдельно от самих копий.

Пример после ручного создания подключения с именем `studio-backup` и контейнера `studio-copies`:

```bash
rclone copy ./backups/studio-2026-11-14 studio-backup:studio-copies/2026-11-14
rclone check ./backups/studio-2026-11-14 studio-backup:studio-copies/2026-11-14
```

Если выбранное хранилище не даёт совместимого хеша, для проверки используйте `rclone check --download`. Эта проверка читает данные обратно и может потребовать трафик. Для конфигурации типа `crypt` учитывайте её путь и возможности проверки. Используйте новые папки по датам, чтобы повреждение или удаление предыдущей копии не распространялось на остальные.

Для регулярного копирования запланируйте на отдельном компьютере вызов CLI, проверку результата и затем `rclone copy`. Выберите время, когда библиотека не редактируется. Сохраняйте код завершения и проверяйте восстановление хотя бы на тестовой площадке. Внешнее резервирование начинает работать после настройки адреса назначения, ключей и расписания.

[rclone copy](https://rclone.org/commands/rclone_copy/) · [Настройка R2 в rclone](https://developers.cloudflare.com/r2/examples/rclone/)

## Дополнительное восстановление D1

Cloudflare D1 Time Travel возвращает базу к прошлому состоянию. По данным Cloudflare, окно составляет до 7 дней на Workers Free и 30 дней на Workers Paid. Если за это время были физически удалены R2-объекты, восстановление D1 может вернуть ссылки на отсутствующие оригиналы. Независимую полную копию сохраняйте отдельно.

[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) · [Импорт и экспорт SQL](https://developers.cloudflare.com/d1/best-practices/import-export-data/)
