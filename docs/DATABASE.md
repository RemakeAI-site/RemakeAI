# База данных

В приложении используется Cloudflare D1 с SQL-миграциями в `database/migrations/`. При локальном запуске Wrangler создаёт эмулированную D1 в каталоге состояния проекта. SQL в миграциях определяет точные типы, ограничения и индексы.

## Основные сущности

| Таблица | Данные и связи |
| --- | --- |
| `categories` | Рубрики. `parent_id` связывает любой уровень с родителем. Имя, slug, описание, цвет, иконка, порядок, состояние и обложка |
| `publications` | Контент TikTok. Связь с рубрикой и системным статусом, название, описание, теги, сценарий, заметки, ссылка, плановая и фактическая даты, версия |
| `ideas` | Идеи с приоритетом, статусом, ссылками, сценарием, заметками и версией. После преобразования остаётся ссылка на публикацию |
| `publication_statuses` | Стабильные идентификаторы статусов и настраиваемые названия, цвета, порядок |
| `media_assets` | Ключи объектов, имя, MIME, формат, размер, SHA-256, размеры, длительность и превью |
| `publication_media`, `idea_media` | Связи с объектами. Порядок, состояние удаления и сведения о замене связи |
| `custom_field_definitions`, `custom_field_values` | Типы и допустимые варианты полей, значения в публикациях |
| `app_settings` | Синхронизируемые параметры студии |
| `activity_log`, `storage_operations` | Действия с материалами и состоянием хранилища |
| `owner_covers` | Активные и удалённые связи обложек и логотипа |
| `archive_exceptions`, `system_state`, `media_cleanup` | Исключения архивной очистки и техническое состояние |
| `upload_sessions`, `upload_parts` | Состояние начатых multipart-загрузок и их частей |
| `backup_records` | Сведения о выполненных резервных операциях |
| `import_sessions`, `import_rows`, `import_objects` | Сессия восстановления, временные данные и состояние проверки копии |

## Почему данные устроены так

- Рубрика может ссылаться на родителя любой глубины. Перемещение проверяется на цикл. Пути и счётчики зависят от фактического дерева.
- Обложка и связи с оригиналами хранятся по ID. Публикация и её копия могут ссылаться на одни и те же байты. Замена одного файла создаёт новый объект.
- Удаление материалов начинается с отметки в базе. Группа удаления сохраняет сведения для восстановления выбранной структуры.
- Стабильные ID статусов — `draft`, `review`, `ready`, `scheduled`, `published`, `archived`. Отображаемые названия можно менять.
- Для плановых дат используется ISO с UTC. Часовой пояс применяется при вводе и показе.
- Индексы ускоряют выборки по связям, датам и состояниям. Все значения пользователя передаются в SQL в качестве параметров.

## Миграции и начальные данные

```bash
npm run db:migrate
npm run db:seed
```

Сид заполняет начальные рубрики, настройки и статусы. Библиотека остаётся пустой. Начальные данные вносятся по стабильным ID, поэтому повторный запуск не создаёт дублей. В новых версиях добавляйте очередную SQL-миграцию, сохраняя уже применённые файлы. Проверяйте миграцию на отдельной базе и делайте копию перед применением к рабочей.

Данные D1 содержат ключи и метаданные R2. Для полного восстановления нужна копия обоих компонентов. Восстановление только SQL сохранит сведения о файлах, но потребует восстановить соответствующие объекты.
